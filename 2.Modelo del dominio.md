# Parte 2 — Modelo del dominio

## Análisis del dominio

El sistema de Brickell's representa el funcionamiento de un boliche y pub bar. Las principales funcionalidades del sistema son la gestión de usuarios, reservas de mesas, sectores, paquetes de consumición, eventos, flyers y entradas anticipadas.

A partir del análisis del negocio se identificaron las siguientes entidades principales:

- Usuario
- Cliente
- Empleado
- Administrador
- Reserva
- Sector
- Paquete
- Evento
- Flyer
- Entrada
- ItemCarta

# Relaciones entre las entidades

Las principales relaciones del sistema son:

- Un **Cliente** puede tener muchas **Reservas**.
- Una **Reserva** pertenece a un **Cliente**.
- Una **Reserva** está relacionada con un **Sector**.
- Una **Reserva** incluye un **Paquete** de consumición.
- Un **Evento** tiene asociado un **Flyer**.
- Un **Evento** puede tener muchas **Entradas**.
- Un **Cliente** puede adquirir muchas **Entradas**.
- Una **Entrada** pertenece a un **Cliente** y a un **Evento**.
- Los usuarios registrados pueden tener los roles de **Cliente**, **Empleado** o **Administrador**.

# Resumen del modelo

El modelo del dominio está centrado principalmente en la entidad **Reserva**, ya que representa una de las funcionalidades principales del sistema.

Las relaciones principales son:

```text
Cliente 1 ───── * Reserva
Reserva * ───── 1 Sector
Reserva * ───── 1 Paquete

Evento 1 ───── 1 Flyer
Evento 1 ───── * Entrada
Cliente 1 ───── * Entrada

Usuario ───── Cliente
Usuario ───── Empleado
Usuario ───── Administrador
```

Este modelo permite representar las principales entidades y relaciones del sistema de Brickell's de forma sencilla, sin incluir todavía la implementación de lógica de negocio, base de datos o funcionalidades del backend.
